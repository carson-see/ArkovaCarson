## Close-out tooling defects — found and fixed during this close (recorded honestly)

None of these touched the evidence; all three are in the capture/rehearsal scripts and
all three are fixed in the committed copies in this directory.

1. **Close-capture guard timezone bug.** `close-capture.sh` parsed `CLOCK_END` with BSD
   `date -j -f` **without `-u`**, so `2026-08-23T09:27:29Z` was read as local EDT
   (= 13:27:29Z). At the real close the guard refused with the self-contradictory
   "now 2026-08-23T09:27:53Z … 239 min remain". The operational copy was patched
   (`-u` on both the BSD and GNU branches) and the capture then ran clean at
   09:28:36Z. The committed copy carries the same one-line fix (line 49).
2. **Same timezone bug in `rollback-rehearsal.sh`** (line 47) — found by inspection
   **before** first run, per the known-bug-class check; without the fix the rehearsal
   would have refused until 13:27Z despite the sealed clock. Patched identically
   (operational + committed copies).
3. **`CLOSE_DIR` glob bug in `rollback-rehearsal.sh`** (line 53): `ls -d $HOME_DIR/close-*`
   also matches the **file** `close-capture.sh`, and `tail -1` picked it (sorts after
   `close-20260823T092836Z`), so `$CLOSE_DIR` was a file. First invocation failed every
   log write ("Not a directory"), which also broke the `2>>"$LOG"` redirect inside the
   pre-deploy docker proof, surfacing as `DOCKER-FAILED` — and the script **aborted
   before any deploy**, exactly as its fail-closed design intends. Fixed to glob
   directories only (`close-*/` + strip trailing slash); second invocation is the PASS
   record above. The rehearsal's serving-state changes happened only on the clean run.
