## What IS covered, and how, for the record

The load generator (`scripts/soak/loadgen.ts`, deployed as Cloud Run service `arkova-soak-loadgen-legacy-soak-2026-08`, `--no-cpu-throttling`, `min-instances=1`) runs continuously against `arkova-worker-legacy-soak-2026-08-staging` for the full window and exercises, generically (not the SS4.3-specific rows above):

- Sustained + periodic-burst HTTP load against `/api/v1/anchor/*` (lifecycle, single-create, bulk-create), `/api/v1/verify/*/proof`, `/api/v1/usage`, `/health` — this is **general worker-health/volume evidence per `CLAUDE.md` §1.12**, not a substitute for the SS4.3 rows' specific changed-path/legacy-surface exercises, which is exactly the distinction §1.12 itself draws ("generic synthetic load is supporting evidence only; it does not substitute for exercising the changed path").
- Edge-case slice: malformed fingerprint (expect 400), over-cap bulk batch >1000 rows (expect 400, no crash), no-API-key request (expect 401/403), duplicate-fingerprint idempotency (expect clean skip, no double charge) — run every cycle.
- Rate-limit path: confirmed live (`X-RateLimit-Limit: 1000`, keyed per API key) is real and enforced, not just present in code, incidentally exercising one column of the "worker — auth/tenant boundary" row's broader auth-middleware stack (but not the specific header-trust defect class named there).
