
application code. **That is not the case on wave3.** Its ~20/min

success count is what it is.

## FD-WAVE3-1 — why the load window starts at 21:50Z, not the clock start

The driver's `refresh_token` was defined but only called from inside the request loop,
gated on a timer pre-seeded to `start_ts`. The gate never opened within a 25-minute run, so
the token file was never created and **every request carried an empty bearer** from the
clock start (16:40:21Z) until the fix at 21:50Z — 5 h 10 m of zero valid load. Fixed and
verified (41/41 at HTTP 200 immediately after), and the window was extended to 12 h of
*loaded* soak rather than counting the empty head. Full detail:
`../findings/FD-WAVE3-1-load-driver-sent-empty-bearer-for-5h.md`.
