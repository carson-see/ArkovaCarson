`5eed0000-…c1` being transitioned `PENDING -> SUBMITTED` at ~18:52Z so Check 5 would pass.

```
  -> 5eed0000-0000-0000-0000-0000000000c1 | ARK-DOC-E5NTRD | PENDING
     updated_at = 2026-08-21 19:00:19.155804+00
```

That `updated_at` is ~8 minutes into the window, not the 18:52Z correction. The single
fixture anchor was moved back to `PENDING` **by this soak's own load driver** — its
`2249-anchor-expiry-sweep` probe runs `jobs/anchorExpirySweep.ts` every pass, and a
SUBMITTED anchor with an expired broadcast is exactly what that sweep reverts.

So the rig self-reverts to `fixture_seeded` under its own load. Re-flipping the anchor
would be a mid-soak write to a live rig that the next sweep pass undoes again; it is
recorded here rather than papered over. Resolving it needs a fixture that the sweep does
not reclaim (or a second, sweep-exempt SUBMITTED anchor seeded before the clock starts) —
and then a fresh clock, because the preflight has to be clean *for the window being
cited*, not before it.
