## Two driver defects found and fixed before the clock was trusted

**1. Token audience — every request was 401.** The driver minted with
`--audiences="${BASE_URL}"`. Against a *tag* URL, Cloud Run rejected the resulting token:
38 × 401 on `/health`, 13 × 401 on `/api/v1/verify/…`, 8 × 401 on `/.well-known/…`,
401 on both cron routes. Manual curls with a plain identity token returned 200 against the
same URL. Fixed by dropping `--audiences`.

**2. The serious one — 401 was counted as SUCCESS.** The classifier treated any 2xx–4xx as
`ok`, so the fully-broken run above reported **`ok: 61, fail: 0`**. A soak driven by that
driver would have produced 12 h of "passing" evidence in which every single request was
rejected — precisely the hollow soak FD-WAVE3-1 describes, one layer deeper. 401/403 now
count as **fail**.

### Why a declared expectation, not a status class

Blanket classification cannot express *"401 is the correct answer here."* For #2220 the
whole point of FD-P7 is that revocation/deletion is **reachable** — a mounted, auth-gated
route answering **401** rather than a missing one answering 404. For #2236 the point is that
Nessie **fails closed** — 503 is the fix working. A deviation from the declared expectation
is the failure, not the raw status class.

load and tripped the §1.10 anonymous limiter (100 req/min/IP): **every probe returned 429**.
The deviation reporting surfaced it immediately. Mountedness does not need high frequency,
so the member block is gated to the same 5-minute cadence as the cron probes.
