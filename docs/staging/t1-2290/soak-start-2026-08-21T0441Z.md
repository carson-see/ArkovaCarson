## Two deploy defects found and corrected before the clock was accepted

**1. Stale `BUILD_SHA` env var.** The first deploy reported
`git_sha: 6ace61c37370028581bd82e935b6c0bec627bc44` — the *previous* wave2 image. Cause:
`gcloud run deploy --image` preserves existing env vars, and `/health` reads `git_sha` from
the service's `BUILD_SHA` env var rather than the baked build-arg. Redeployed with
`--update-env-vars BUILD_SHA=a7ac4abd…`. **Any soak evidence captured before this fix would
have shown the wrong head SHA and been rejected on inspection.**

**2. Apparent image-digest mismatch — investigated, benign.** The push reported digest
`sha256:d1d0130c…` while the revision referenced `sha256:942b2c19…`. Resolved by inspecting
the manifest rather than assuming:

```
mediaType: application/vnd.oci.image.index.v1+json
  child sha256:942b2c19…  linux/amd64
  child sha256:2cb3b774…  unknown/unknown
```

`d1d0130c` is the OCI **image index**; `942b2c19` is its `linux/amd64` child, which is what
Cloud Run resolves and runs. The deployed revision is the correct build. The redeploy pins
the index digest explicitly so the reference is unambiguous.

## Load — third defect: the tag name was rejected, so the first 31 min carried no load

The relauncher's `wave2` leg was first repointed to the **`t1-2290`** tag URL. Every cycle
then failed instantly:

```
::error::Load harness failed: STAGING_API_BASE must be a tag-routed per-PR or named train
Cloud Run URL; received host `t1-2290---arkova-worker-wave2-2026-08-staging-…`
```

`scripts/staging/load-harness-env.ts:18-24` allows **only** `pr-<digits>` or
`train-[a-z0-9-]*`:

```ts
function isAllowedTag(tag: string): boolean {
  if (tag.startsWith('pr-')) { /* digits only */ }
  return /^train-[a-z0-9-]*[a-z0-9]$/.test(tag);
}
```

`t1-2290` matches neither, so the harness refused to start and the rig received **only the
five manual health probes** between the clock start (04:41:33Z) and the fix (~05:12Z) —
roughly **31 minutes of unloaded clock**.

**The liveness gate caught this**, logging `[wave2] cycle done rc=1` followed by
`SOAK IS NOT PRODUCING VALID EVIDENCE — do not count this window.` It is the gate's first
true positive on a real load outage.

### Fix — tag renamed WITHOUT a new revision

`gcloud run services update-traffic --set-tags pr-2290=…-00003-qiz` attaches the correctly
named tag to the **existing** revision, so the clock is not reset. Verified afterwards:

```
latestReadyRevisionName : arkova-worker-wave2-2026-08-staging-00003-qiz   (unchanged)
creationTimestamp       : 2026-08-21T04:41:33.519799Z                     (unchanged)
```

`pr-2290` health: 3/3 × 200, `git_sha` still `a7ac4abd…`, `database`/`anchoring`/`kms` ok.

Harness acceptance proven with a 2-minute run against the new URL — **323 requests,
`cron ok=5` at HTTP 200**, evidence written to `load-proof-pr2290.json`.
