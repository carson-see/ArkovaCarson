2.4 Why bulk uploads fail and extraction is slow — root causes proven in prod

  • The big one: anchors.fingerprint is character(64), but bulk_create_anchors declares its comparand text. Postgres therefore casts the indexed column and no index is usable. EXPLAIN on prod: cost 1,783,431 (seq scan) versus 2.78 (index scan) — 649,000×, per row — one probe per row, inside a per-user advisory lock. It is O(N²) during backfill, which is exactly your million-document case. Same bug class as SCRUM-3031, fixed in batch_insert_anchors by migration 0370 and never fixed here. The fix is a type declaration.
  • AI extraction: the client sends all rows to an endpoint capped at 50, so every CSV over 50 rows fails deterministically. A client/server contract mismatch, not a model problem.
  • Body cap: express.json() has no limit, so body-parser's 100 kb default applies against a documented 1000-row API cap — 413 at roughly 400–850 rows.
  • Confidence gate: live at 0.4 (ANCHOR_CONFIDENCE_THRESHOLD unset in prod). Sub-threshold anchors revert to PENDING. Prod currently has 0 PENDING, so it is a hazard rather than an outage. Removing it is your call — note confidence is required in the published OpenAPI, so dropping the field breaks partner clients with generated code.

Full detail: docs/design/bulk-upload-verified-root-causes-2026-08-20.md.

4. The uncomfortable finding

You said "all this should've been caught in the soak, that's why we did it." You were right, and the reason is worth keeping.

Soak health was judged by "did the clock run and is /health green", never by "did the soak exercise anything." Under those criteria a soak measuring nothing looks identical to a healthy one. Four separate instances in one window:

  • wave3's driver sent an empty bearer token for 5 hours 10 minutes — every request failed, dashboard green.
  • TRAIN-4's driver returned 401 on every path including /health while reporting ok=61, fail=0, because the classifier counted any 2xx–4xx as success.
  • Ambient anchor traffic (~36/day) can never reach the Trigger A/B thresholds that T3 requires — a soak could run for weeks and evidence neither.
  • The load agent silently died for 26 minutes and nothing noticed.

Separately: wave2's entire 12-hour window was worthless for its API members because one row was missing from that rig's switchboard_flags, so /api/v1 fail-closed at sub-10 ms 503s while everything looked healthy.

4.1 What is now enforced in code, not in a checklist

  • Liveness gate (merged, #2299) — asserts evidence exists, is fresh, and reports ok > 0. It has already caught a real load outage.
  • ENABLE_VERIFICATION_API seeded at provisioning (#2306) — the wave2 failure cannot recur.
  • 401/403 count as failure in the load driver.
  • Per-member probes with declared expectations, written into the evidence file — coverage is auditable from the artifact rather than asserted in prose.
