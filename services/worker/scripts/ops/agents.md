# services/worker/scripts/ops/agents.md

Operator-run scripts for production or sandbox verification. Keep commands safe by default: read-only checks should be the default mode, and any command that can enqueue work in production must require an explicit opt-in flag and document the side effect.

## Files

- `docusign-connect-smoke.ts` — SCRUM-1655 DocuSign Connect smoke helper. Default `orphan` mode verifies invalid-HMAC rejection and signed unknown-account acknowledgement without touching integration state. `accepted-duplicate` mode can enqueue a real rule event/job and must only be used with a connected DocuSign sandbox account plus `--allow-processing`. Protected Cloud Run staging targets can use `WORKER_BEARER_TOKEN`; keep bearer tokens and HMAC secrets in env, never argv.
- `ce-secret-manager-smoke.ts` — SCRUM-2376 (CE-05) Credential Engine API key Secret-Manager runtime smoke. Proves the CE Registry API key resolves from **Secret Manager** (`versions/latest:access`, mirrors the `docusign-token-store` REST pattern), is **never logged** (`redactCeSecret` → `[REDACTED_CE_SECRET]`; only key length is surfaced), and drives **3–5 read-only (GET) Registry calls** (Graph Search + GetRecord) with **bounded** (≤280 char) body snippets. Default mode is **mock/offline** (CI-safe, no GCP/network, no env-baked key — there is intentionally no `process.env` key fallback). `--live` mode (operator box with `roles/secretmanager.secretAccessor`) hits real Secret Manager + the Registry; runbook + flags are in the file header. Example/Registry failures are recorded, not fatal. Running it publishes nothing and implies no Registry listing (§1.13 R-7).
