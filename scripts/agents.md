# scripts/agents.md

Operational, CI, deployment, and security scripts. Run manually or from CI workflows.

## Key subdirectories
- **`ci/`** — CI gate scripts (has its own agents.md).
- **`fixtures/`** — test fixtures read by `scripts/*.test.ts` via `readFileSync` (stored `.txt` so repo typecheck/eslint never parse them; may deliberately contain banned copy terms — do not "fix").
- **`agent/`** — local agent bootstrap helpers, including the `CLAUDE.md` acknowledgement required before staging/prod-sensitive commands.
- **`gcp-setup/`** — GCP infrastructure provisioning (service accounts, BigQuery, SLOs, Cloud Scheduler).
- **`healthcheck/`** — credential + external-service smoke tests.
- **`ops/`** — operational scripts (pg_cron management, pipeline dashboard cache).
- **`security/`** — license denylist scanner (blocks AGPL/GPL/SSPL).
- **`staging/`** — staging environment tooling (deploy, migrations).
- **`uat/`** — UAT screenshot capture scripts.
- **`admin/`** — admin provisioning scripts (sandbox orgs).
- **`kpi/`** — partner-KPI reconciliation tooling (has its own agents.md). HakiChain LOI KPI #2 weekly reconciliation lives here; sibling to `kpi3/` (KPI #3) but a separate directory/data-source.
- **`kpi3/`** — KPI #3 (independent, non-issuer verification) clean-room tooling: `external-verify.mjs` (dependency-free public-explorer verifier) + `haki-provision-plan.mjs` (KPI #1 provisioning DRY-RUN planner, founder-gated).
- **`kpi3/`** — HakiChain KPI tooling (`external-verify.mjs`, `haki-bundle-verify.mjs`, `haki-provision-plan.mjs`). Standalone `node --test` `.mjs` files, not wired into `npm run test`/CI — run manually. `haki-provision-plan.mjs` builds a DRY-RUN-only `POST /api/v1/anchor/bulk` request body for an operator-chosen `--count` of real anchors; it does **not** compute anything from `org_credits.anchor_quota` (that framing — "shortfall to reach the quota" — was retracted 2026-08-01; see the file's own header and `memory/project_hakichain_account_state.md`). Its continued existence is a standing CTO question, not settled by this note — see the file header for the recommendation.
- **`kpi/`** — HakiChain KPI-2 weekly reconciliation (`haki-weekly-reconciliation.ts`). Read-only, GET-only against prod; see `docs/partners/hakichain-kpi-reconciliation.md` for usage.

## Copy-term linter (`check-copy-terms.ts`, SCRUM-2149 / SCRUM-2148)

**Scope (`shouldCheck` / `INCLUDE_ROOTS`):** scans `src/components/`, `src/pages/`, `src/lib/`, `src/hooks/`, and `packages/embed/src/` (the PUBLIC embeddable widget). Pre-2149 it scanned only `src/components` + `src/pages`, so banned terms in shared utilities, hooks, and the public widget shipped while the gate stayed green. Excludes (`EXCLUDE_PATTERNS`): `**/*.test.ts(x)`, `src/components/ui/**` (primitives), `src/components/admin/treasury/**` (internal ops). **`src/lib/copy.ts` is NOT excluded — it IS scanned** (UX-03 follow-up, 2026-07-06): it is the largest user-facing copy surface, and the old blanket exclude let banned terms ship silently (e.g. "worker service" in `USAGE_UNAVAILABLE`). Its sanctioned SCRUM-1672 "Issue Credential" strings pass via the sanctioned-copy allowlist (below), not by excluding the whole file. `main()` walks roots via `collectCandidateFiles()`, derived from `INCLUDE_ROOTS` so coverage and `shouldCheck` cannot drift.

**Detection model — only USER-VISIBLE copy flags:**
- `FORBIDDEN_TERMS` — every §1.3 banned word, with **two deliberate boundary styles**:
  - **Hyphen-guarded** `(?<![-\w])X(?![-\w])` — a hyphen adjacent to the term blocks the match. Used **only** for `block` and `gas`, which collide with Tailwind/CSS utilities (`inline-block`, `text-block-fg`). The hyphen carve-out is needed there and **nowhere else**.
  - **Word-boundary** `(?<!\w)X(?!\w)` — a hyphen adjacent to the term **still flags**. Used for the chain/marketing terms (`bitcoin`, `blockchain`, `crypto`, `cryptocurrency`, `testnet`, `mainnet`, `utxo`, `broadcast`) so hyphenated hero copy like `Bitcoin-anchored` / `Crypto-secured` / `UTXO-based` / `Re-broadcast` flags (SCRUM-2149 review B1). className values are stripped upstream and identifier/type positions are dropped by `isCodeIdentifier()`, so the hyphen guard is unnecessary for these. (`wallet`/`hash`/`transaction`/`mining`/`token` keep the hyphen guard — strictly safer, no known hyphenated-copy case.)
- `isCodeIdentifier()` (the structural filter, 2149d; decomposed into named predicates per review N3 — `isJsxComponentName`, `isPropertyAccess`, `isObjectKey`, `isUrlSegment`, `isBareValueString`, `isJsxVisibleText`) drops matches in code positions that are never copy: JSX component/closing-tag names, property access (`obj.bitcoin`), TS `type`/`interface` declaration lines (union members), object-key position (`mainnet:` / `'mainnet':`), URL literals & path segments (`/block/`, `https://…/testnet`), and **bare in-code value strings** (a quoted string whose entire content is exactly the term, e.g. `'token'`, `|| 'mainnet'`). Two of these — URL-segment and bare-value — are **gated on `!isJsxVisibleText`** (review N2): they will NOT suppress a banned word that sits in visible JSX element text (between `>` and `<`), so `<p>Testnet/Mainnet</p>` flags both terms and `<p>"Bitcoin"</p>` / `<button>'Broadcast'</button>` flag. The bare-value skip also does NOT apply to JSX/HTML attribute values (`placeholder="Wallet…"` — preceded by `=`), which still flag.
- `findRawEnumRenders()` + `RISKY_ENUM_FIELDS` (2149c) — flags a RAW DB-enum render: a bare `{X.status}` / `{X.credential_type}` / `{X.anchor_status}` / `{X.network}` used as a JSX expression CHILD. A child is the whole (trimmed) line, an inline `>{…}<`, **or an expression preceded by leading text** when a tag has closed (`>`) earlier on the line and a tag (`<`) follows (review N1: `<div>Label: {row.status}</div>` now flags). Ignores `${res.status}` template interpolation, `status={x.status}` / `key={x.status}` attribute positions (excluded by the leading boundary class `[^$=\w.]`), non-risky fields, and non-`.tsx` files. Fix = route the value through a display mapper in `src/lib/copy.ts` (`ANCHOR_STATUS_LABELS`, `formatCredentialType`, …). Keep the risky-field set small.
- `scanFileContent()` — **cross-line JSX element-text tracking (2026-07-06, SCRUM-2666, PR #1433 follow-up).** The per-line term scan used to short-circuit any line with no quote char and no same-line `<`/`>` pair, so a banned term on its OWN raw JSX text line (`<p>` … wrapped paragraph text … `</p>`) was never scanned — the blind spot that shipped the literal "Bitcoin blockchain" to prod in `src/components/verification/PublicVerification.tsx:658`. `scanFileContent` (`.tsx` files only — JSX can't appear in `.ts`) now runs a per-line **context-stack** machine: plain code at the bottom, a `text` frame per open element/fragment, an `expr` frame per `{…}` opened from text — so copy inside `{cond && (…)}` conditional renders, `.map()` callbacks, and `<>…</>` fragments is tracked, and a closing tag pops back to the PARENT context. Lines whose current context is `text` (and that contain no `<`) are force-scanned via `findTermViolations(…, jsxTextContinuation=true)`: balanced `{…}` expressions are blanked (code, not copy) and every remaining forbidden match flags with **no** `isCodeIdentifier` suppression. In TEXT context only `{` and `<` are structural — apostrophes/quotes/slashes in prose can't corrupt state; in CODE/EXPR contexts the walker skips strings, multi-line template literals, `//` + `/* */` comments, and regex literals, and vetoes non-tag `<` (identifier-adjacent `Array<string>`/`a<b`, and the TSX generic-arrow spellings `<T,>` / `<T extends …>`). Tag bodies are walked with `{}`-depth + quoted-attr + attr-template awareness (a multi-line `` className={`… ${ `` template is opaque until its closing backtick — the ApiSandbox shape). Adversarially reviewed round 2: a repo census of force-scanned lines shows 0 code-shaped lines across all 356 scanned files. Regression fixture: `scripts/fixtures/copy-terms-multiline-jsx.fixture.txt` (stored as `.txt` so repo typecheck/eslint never parse it — do NOT "fix" its banned terms). **Accepted approximations:** plain-`<T>` generics in TSX type positions and generic component instantiations (`<Select<Option> …>`) can misread; a backtick inside a template interpolation (nested template) is not tracked; prose like `a<b` (letter-abutting `<` in copy) can open a phantom tag; multi-line template literal CONTENT is not scanned (it's skipped as code).
- **Deliberate heuristic blind spots (do NOT over-trust the gate):** the raw-enum detector targets the bare `{ident.field}` shape only. It does **not** flag a defaulted child `{x.status || ''}`, a call-result child `{getX().status}`, a template-literal child `` {`${x.status}`} ``, a multi-line JSX child split across lines, or any risky field accessed via bracket notation `{x['status']}`. These are accepted false-negatives to keep false-positives near zero; a banned literal rendered through any of them must be caught in review or via a `src/lib/copy.ts` mapper. A single banned WORD hyphen-wrapped across two lines (`Bit-\ncoin`) is still not caught (no un-wrapping); whole banned terms on their own JSX text lines ARE caught since the `scanFileContent` cross-line fix above.
- All hot-path regexes are pre-compiled at module scope (`FORBIDDEN_REGEXES`, `RAW_ENUM_CHILD_RE`, `LEADING_BRACE_EXPR_RE`, `ENUM_FIELD_RE`); patterns are bounded — character classes exclude their delimiter (`[^}]*`) and there are no nested/lazy quantifiers or `\s+$`-style anchored runs, so they are **ReDoS-safe** (SonarCloud S5852/S6594 clean; review B3 replaced the `replace(/\s+$/,'')` and lazy `.match(/…[^}]*?…/)` with `.trimEnd()` + non-lazy `RegExp.exec`).

**Grandfather baseline protocol (`scripts/ci/snapshots/copy-terms-baseline.json`):** records ONLY pre-existing violations that cannot be fixed in the current PR (a file locked by another open PR, or a fix owned by another in-flight track). The linter partitions current violations against the baseline (match key = normalised `file`+`line`+normalised `term`, separated internally so a different violation on the same file:line is still NEW and build-failing) and fails ONLY on NEW ones. Stale entries (baselined file:line+term no longer violating) print a non-fatal warning to prompt cleanup. `loadBaseline()` fail-closes (treats a missing/corrupt baseline as empty → everything fails). **Never baseline a violation you are introducing** — fix at source or use a mapper. Each entry must carry a `reason`. Retire entries; never extend them as a workaround.

**Copy-term sanctioned allowlist (`scripts/ci/snapshots/copy-terms-allowlist.json`, UX-03 follow-up):** distinct from the grandfather baseline. The baseline is **transient debt** (pay it down); the allowlist is **permanent §1.3 policy** — copy that §1.3 itself sanctions and will never be "fixed." Today its sole use is the SCRUM-1672 "Issue Credential" restricted-issuance strings in `src/lib/copy.ts`. Pipeline order in `main()`: violations → `partitionAgainstAllowlist` (pardon sanctioned) → `partitionAgainstBaseline` (grandfather debt) → `fresh` fails. Key differences from the baseline, by design:
- **Keyed on normalised `(file, term)` — NO line number.** `copy.ts` is the most-churned file in scope; a line-keyed carve-out would go stale on every edit. `(file, term)` is drift-immune.
- **Fail-closed to a tiny vocabulary.** An entry may ONLY name a term in `ALLOWLISTABLE_TERMS` (currently just `issue credential`); `loadAllowlist()` drops any entry naming anything else, and a NEW term needs a reviewed code change to `ALLOWLISTABLE_TERMS` before it can be allowlisted. Term-scoped: a *different* banned term on a sanctioned line still fails.
- **Non-suppressible guard (`isNonSuppressibleTerm`).** BOTH the allowlist AND the baseline refuse to silence secret-leak terms (`service_role`, `service role`, `postgrest`), the infra leak `worker service`, and every `LAUNCH_BLOCKER_COPY_TERMS` entry — such a violation is ALWAYS `fresh` even with a matching allowlist/baseline row. This closes the pre-existing hole where a category-blind baseline row could have grandfathered a `service_role` leak. **Never** widen a hard-block regex to dodge a false positive; reword instead.

**Upstream suppression must not hide a non-suppressible leak (code-review/pre-mortem hardening, 2026-07-06):** the partition-time guard above only sees violations that were actually *created*. Two suppression layers run BEFORE creation, so the guard is also enforced there:
- **`isCodeIdentifier` (structural filter):** a non-suppressible term bypasses it — a bare-value `'service role'` or an object-key-position secret still flags. Ordinary vocab terms still respect it (so copy.ts's own `FORBIDDEN_TERMS`/`TERM_REPLACEMENTS` bare-value DATA stays suppressed and doesn't red the file).
- **`shouldSkipLine` (whole-line skip):** a skipped **code** line is still scanned for non-suppressible terms only (so `toast('service_role fail'); el.scrollIntoView()`, a secret on a `cryptographic` line, or a secret behind a trailing `// crypto.subtle` comment still flags). **Comments/imports are exempt** — they are not shipped copy and legitimately mention infra terms.

**Accepted residuals (documented, not fixed here — follow-up material):**
- **Single-word VOCAB bare-values in copy.ts** (e.g. `LABEL: 'Wallet'`) are still suppressed, because copy.ts legitimately holds bare-value banned terms in its `FORBIDDEN_TERMS` list + `TERM_REPLACEMENTS` map (a line-by-line scanner can't tell that data from shipped copy). Non-suppressible (secret/launch-blocker) bare-values ARE caught; only single-word §1.3 *vocabulary* values slip. Clean fix = move that linter-vocab DATA out of copy.ts, then drop bare-value suppression for copy.ts. Mid-phrase vocab (`'Broadcast now'`) already flags.
- **VOCAB terms on `cryptographic` / `crypto.subtle` / `crypto.getRandomValues` / `scrollIntoView` / `searchParams.get` lines** are whole-line-skipped (those are code-construct / adjective tokens that ~never co-occur with a banned VOCAB word in copy.ts strings). SECRETS on such lines ARE caught (checkFile re-scans them). Known live instance of the `cryptographic` case OUTSIDE copy.ts: `AssetDetailView.tsx` renders "SHA-256 cryptographic hash" (§1.3 "hash") — pre-existing, masked by this skip; tracked as a separate reword (it sits on the `src/components/anchor/` T2 surface, so it is NOT bundled into this T1 tooling PR). Removing the `cryptographic` skip would surface it (its blast radius is that one line) — do it in the anchor-lane fix, not here.
- **Allowlist `(file, term)` key** pardons `issue credential` anywhere in copy.ts, not only the `ISSUE_CREDENTIAL_LABELS` block — a deliberate drift-immunity trade-off. A *different* banned term on those lines still flags, and a new generic-action misuse is caught in review; tighten later by keying on the enclosing const-name if needed.

## Conventions
- Deploy scripts must use `linux/amd64` images and full 40-char Git SHAs.
- Live isolated-rig provisioning must fail before mutation unless the operator supplies a digest-pinned image whose digest also resolves from the declared full-SHA Artifact Registry tag, an explicit source HEAD matching local `git HEAD`/`GITHUB_SHA`, tracked provisioner + driver bytes matching that commit, a freshly fetched `origin/main` base, and an exclusive soak ID. Dry-runs may emit labeled placeholders only.
- Scheduler-backed isolated rigs create jobs on a non-firing hold schedule, immediately pause and verify them, keep them paused through fixture seed plus `clean_mirror`, then restore the existing configured cadence and resume only after the timestamped preflight artifact is recorded. Stubbed apply tests must put admission artifacts under their temporary directory; they must never leak `docs/staging/**` files into the worktree.
- CI scripts exit 0 = pass, exit 1 = fail with actionable message.
